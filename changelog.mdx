# Changelog

Follow this page for major Pin updates, new workflows, and important changes that affect how your team uses the app.

<Update label="November 21, 2026" tags={["AI","Pins","Procedures","Chat","Web","Mobile"]} description="Weekly release: clone Pins, duplicate detection, AI file imports for procedures, and more">
  A batch of workflow additions this week.

  **Clone Pins.** Any Pin can now be cloned into a new Pin from the three-dot (⋯) menu, on both web and mobile. Every field carries over — title, assignee, checklist, followers, linked equipment and inventory, attachments, and more. A review screen opens with everything pre-filled so you can adjust before submitting. Chat history does not carry over. See [Cloning a Pin](/pins/managing-a-pin#cloning-a-pin).

  **Duplicate Pin detection.** PIN's AI now checks every new [Pin](/pins/managing-a-pin#duplicate-pin-detection) against existing open Pins to catch potential duplicates. If a match is found, a **Potential duplicate detected** banner appears on the Pin's Info tab with a plain-language explanation of the match and the distance to the potential duplicate. Two options: **Not a duplicate** (keeps the Pin active) or **Cancel duplicate** (cancels this Pin). Available on web and mobile.

  **AI procedure creation now accepts more file types.** The AI generator in the [Procedures](/modules/procedures#build-a-procedure-with-ai) module now accepts PDFs, Word documents, spreadsheets (XLSX), CSV files, and images. Upload any of these — a printed inspection sheet, a spreadsheet of routine items, an existing SOP — and PIN's AI extracts the checklist automatically.

  **New Pin filters.** The [Pin list view](/viewing-navigating/list-view-filters-groups#filters-search) now includes filters for **Potential Duplicates**, **Linked Equipment**, **Linked Inventory**, and **Attachments** — making it easier to surface Pins that need cleanup or have specific context.

  **Chat Updates mode stays on.** In [Chat](/communication/chat#messages-vs-updates), the **Updates** mode now stays on once enabled, so you can post multiple Updates in a row without re-selecting it each time. Turn it off manually when you're back to regular messages.

  **Additional improvements** shipped this week but not requiring separate documentation include: expanded QR-code workflows (printable labels, bulk label printing, PNG downloads), redesigned mobile project details, sorting Pins within groups by due date, creation date, or title, standardized timezone behavior with clearer labels, recurring Pin attachments scoped to current instance or current-and-future, group management selector polish, "Manage All" document permission for authorized roles, vendor contact form validation, refreshed mobile vendor profiles, Pin CSV exports preserving active sorting, mobile privacy warning before sending photos to AI, plus a batch of mobile reliability fixes including logout clearing notifications and the app badge.
</Update>

<Update label="August 27, 2026" tags={["AI","Pins","Projects","Map","Equipment","Vendors","Incidents","Analytics","Web","Mobile"]} description="Batch release: AI safety detection, project workflow upgrades, map previews, QR codes, CSV exports, and more">
  A large batch of improvements across the platform.

  **AI safety-risk detection.** When creating a [Pin](/pins/creating-a-pin), PIN's AI now evaluates the title, description, and any Snap-to-Pin photo for urgent safety risks — exposed wiring, spills, hazards. A **Safety Risk Detected** banner appears with two options: **Mark as High Priority** or **Dismiss**. If dismissed or ignored, the Pin is not automatically marked as priority. Available on both mobile and web.

  **Project workflow upgrades.** [Projects](/modules/projects) received several enhancements:

  - **Category comments** — every project category now has its own comment thread for updates and coordination that isn't tied to a specific Pin.
  - **Category selection during Pin creation** — when adding a Pin to a project, select the category directly from the create screen.
  - **Project log** — every action on a project (Pin adds/removes, category changes, follower changes, status changes, document uploads) is recorded. Accessible from the **Logs** button on the web app's project page or the three-dot menu on mobile.
  - **Project Chat in the Chat module** — project chats now surface in the main [Chat module](/communication/chat) alongside your other conversations, filtered under the **Projects** tab. Identified by a project file icon.

  **Map previews (web).** On the web app, clicking any location, Pin, or equipment item on the [map](/viewing-navigating/map-view) opens a preview panel with the most useful information at a glance — status, active work, emergency contacts for locations, condition and department for equipment. Every preview includes an **Open details** button.

  **Equipment ↔ Vendor linking.** Each piece of [equipment](/modules/equipment) can now be linked to one [vendor](/modules/vendors). The link can be created from either the equipment detail page or the vendor's profile. On the vendor profile, linked equipment appears in its own section alongside linked inventory.

  **QR codes for Equipment and Inventory.** Generate printable QR codes from the web app: bulk-select items from the Equipment or Inventory list view, then click **Actions** to generate a printable sheet. On mobile, tap the QR scanner button at the top of the [Overview screen](/viewing-navigating/overview-dashboard) to open the camera — scan any code to jump directly to the linked record.

  **CSV exports across list views.** Every list view page now has an **Export** button at the top right — Pins, Recurring Pins, Groups, Projects, Incidents, Equipment, Inventory, Locations, Documents, Vendors, Procedures, Users, Departments, and more. Exports respect any filters applied.

  **Daily summary email for managers.** Every manager now receives a daily email summarizing yesterday's operational activity — completions, creations, active members, time logged, department activity. Users can unsubscribe from their profile settings.

  **Incident filter enhancements.** [Incidents](/modules/incidents) now includes dedicated **Medical** and **Slip-and-Fall** filter categories for easier reporting on the most common incident patterns.

  **Additional improvements** shipped in this release but not requiring separate documentation include: recurring Pins preserving checklist sections when cloned, refreshed dashboard navigation and settings, cleaner "Remove all" follower actions, activity histories opening in side panels, project chat photo sharing and mentions, auto-follow for locations from search, platform-wide mobile search, and various mobile reliability improvements.
</Update>

<Update label="July 10, 2026" tags={["AI","Procedures","Recurring Pins"]} description="Build procedures and checklists with AI">
  You can now generate [**procedure templates**](/modules/procedures) and recurring Pin checklists in seconds with AI. Tap the sparkle icon ✨ on the create screen and choose one of three inputs:

  - **Take a photo** of a physical checklist — a printed form, laminated sheet, or wall-mounted inspection card.
  - **Upload a file** — a PDF, doc, or image of an existing checklist or SOP.
  - **Describe it** — tell the AI what kind of checklist or procedure you want and it will draft the items for you.

  Review, edit, and save. Available on both **mobile** and **web**.
</Update>

<Update label="July 8, 2026" tags={["Locations"]} description="Location Status">
  Every [**location**](/modules/locations) now has a status that shows its current operational state. Tap the status pill at the top of the location page and pick from:

  - **Operational** (green) — default state; the location is functioning normally.
  - **Occupied** (blue) — the location is currently in use.
  - **Needs Attention** (amber) — something at the location requires review or follow-up.
  - **Out of Service / Closed** (red) — the location is not currently usable, or is closed.
  - **Vacant** (grey) — the location is empty or unoccupied.

  Any user with access to the location can change its status. Inside the Locations module, filter the list by status to see every location in a given state at a glance.
</Update>

<Update label="July 3, 2026" tags={["Vendors","Inventory"]} description="Vendors module released">
  A new [**Vendors**](/modules/vendors) module gives your venue one place to track every external party you work with — vendors, contractors, and suppliers.

  - Each vendor profile stores basic info, a **Contact List** with multiple contacts (one can be marked **Primary**), and the **inventory items** sourced from that vendor.
  - Inventory items are now linked to a real vendor profile — this **replaces the old free-text Supplier field**. From an inventory item, see which vendor supplies it. From a vendor profile, see every item they supply.
  - **Documents** can be uploaded directly to a vendor profile — contracts, W9s, certificates of insurance, price lists, and more. Each document has its own permission layer: **Public** (anyone who can view the vendor) or **Specific access** (selected users and/or departments). Vendor documents also surface in the [Documents module](/modules/documents).
  - Vendors are **scoped by department** — you can see and edit vendors that belong to your department(s). Admins and All-Teams Managers see every vendor across the venue.

  Find Vendors as a top-level module in the sidebar, alongside Documents and Procedures.
</Update>

<Update label="June 30, 2026" tags={["Procedures","Checklists"]} description="Procedure templates and collapsible checklist sections">
  Save reusable checklists once and apply them anywhere. The new **Procedures** library stores standard checklists — opening walk-throughs, equipment inspections, turnover routines — that any user can pull into a Pin or Recurring Pin.

  - When adding a checklist, choose **New checklist** to build from scratch or **Use template** to pull from a saved [procedure](/modules/procedures).
  - Procedures are venue-wide. Any user can create one, and every user can see and use every procedure.
  - **Checklist sections** let you organize long checklists into collapsible groups — works on procedures, Pins, and Recurring Pins.
  - Edits to a procedure template are **not retroactive** — they only affect Pins and Recurring Pin instances created after the edit.

  Find Procedures under **Library → Procedures** on web and **More → Procedures** on mobile.
</Update>

<Update label="June 12, 2026" tags={["Documents"]} description="Documents module released">
  Documents now sit throughout PIN — upload them to **Equipment, Locations, Pins, Incidents, and Projects**, wherever the work happens. A new central **Documents module** surfaces every document you have permission to view in one place, so you can find any file without navigating into individual records.

  Document access depends on where the document is uploaded:

  - **Pins, Incidents, and Projects** — documents are visible to the followers of that parent record.
  - **Equipment and Locations** — when uploading, the uploader chooses **Public** (anyone on the platform) or **Specific access** (selected individual users and/or entire departments).

  Documents stay attached to their source — the Documents module is an access layer, not a separate storage location.
</Update>

<Update label="June 3, 2026" tags={["Tenant Portal"]} description="Per-QR routing and submitter email opt-in">
  Tenant Portal routing is now set **per QR code**, not at the organization level. When generating a QR code from the **Pin QR Generator**, admins choose which team receives submissions from that specific code — so different codes across the property can route to different departments.

  Submitters can now also opt in to email updates when filling out the request form. If they opt in, they receive emails as the Pin's status changes from intake through completion.

  The Tenant Portal routing setting has been removed from Organization Settings.
</Update>

<Update label="June 3, 2026" tags={["Web","Locations","Tenant Portal"]} description="Team-routed QR code generator">
  A new Pin QR generator replaces the separate property-wide and location QR dialogs with a single tool that routes scanned [requests](/modules/tenant-portal) to the right team.

  - Generate a QR code from the overview or any [location](/modules/locations) page and pick the team (for example, Front Desk or Housekeeping) that should receive submissions.
  - Optionally lock the code to a specific location so submitters cannot change it after scanning.
  - The submission form now shows the routed team as read-only context, so requesters can see where their report is going.
  - QR links are signed, so tampered or outdated links prompt the submitter to scan a freshly generated code.

  The previous tenant-wide "default QR department" setting has been removed — routing is now chosen per QR code at generation time.
</Update>

<Update label="June 2, 2026" tags={["Mobile","Notifications"]} description="Push notifications follow account switches">
  Mobile push notifications now reliably move with you when you switch accounts on the same device.

  Previously, a device could keep delivering notifications to a previous account after logout — especially when switching between organizations. The app now reassigns the device to your current account on sign-in, so [notifications](/onboarding/chat-and-notifications) go to the right place.
</Update>

<Update label="June 2, 2026" tags={["Mobile","Pins"]} description="Group badge respects department filters">

<Update label="June 2, 2026" tags={["Web","Mobile","Security"]} description="Security and reliability improvements">
  Behind-the-scenes updates this week harden Pin's network handling on web and mobile.

  - Stronger protection against prototype-pollution-style payloads on requests that accept structured form data.
  - Fixed a case where HTTPS traffic could fall back to cleartext when routed through certain proxy configurations.
  - More resilient file upload progress reporting, so uploads no longer fail on browsers that emit malformed progress events.
  - Non-ASCII characters in request headers are now preserved end-to-end, improving support for internationalized data.

  No action is required.
</Update>

<Update label="June 1, 2026" tags={["Web","Mobile","Projects","Roles","Permissions"]} description="Project permissions">
  Projects now have their own role-based permissions, matching how Incidents work today.

  - **View All** — see every project; without it, users only see projects they follow.
  - **Create**, **Edit**, **Delete** — gate the matching project actions on web and mobile, including category, follower, document, and linked-Pin changes.

  Admin and System roles automatically receive all four project permissions. For other roles, an admin needs to grant them under **Settings \> Roles & Permissions** before users can create, edit, or delete projects. Until then, those actions return a permission error and are hidden in the UI.

  See [Roles and permissions](/getting-started/roles-permissions) for how to update role access.
</Update>

<Update label="June 1, 2026" tags={["Web","Pins","Incidents"]} description="Easier follower management">
