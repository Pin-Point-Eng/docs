# Changelog

Follow this page for major Pin updates, new workflows, and important changes that affect how your team uses the app.


<Update label="June 1, 2026" tags={["Web"]} description="Consistent confirmation dialogs">
  Confirm and delete prompts across the web dashboard now share a single, consistent dialog.

  - Deleting a chat announcement now opens a standard confirmation dialog with a clear description, instead of an in-place hover prompt that could be dismissed by accident.
  - All confirmations—deleting [Pins](/pins/managing-a-pin), Pin groups, [Incidents](/modules/incidents), projects, equipment types and manufacturers, inventory categories and suppliers, emergency contacts, roles, users, and teams, plus removing followers and disconnecting SSO—now behave the same way, with focus on the action buttons and a loading spinner while the change is saving.
  - Outside-clicks no longer close a confirmation by accident.
</Update>

<Update label="June 1, 2026" tags={["Web","Mobile","Pins"]} description="Department-scoped Pin groups">
  Pin group browse surfaces now filter by department. The web Groups page, the "Groups only" chip, the mobile group filter, and the mobile Pins-tab count badge all show only groups containing Pins you can see.

  Empty groups still appear for everyone so newly created groups stay visible, and admins with full access continue to see every group. Add-pin selectors are unchanged, so you can still add a Pin to any group regardless of department.
</Update>

<Update label="June 1, 2026" tags={["Web","Pins","Incidents"]} description="Easier follower management">
  Adding and removing [followers](/pins/managing-a-pin#followers) on Pins and [Incidents](/modules/incidents) from the web dashboard is now much faster.

  - Follower chips show an `×` on hover with a confirmation prompt, so you can remove a follower directly from the followers list without opening the picker.
  - The Select Followers picker now auto-expands departments that already contain followers, shows an "N selected" badge on each department, and displays a running total of selected followers.
  - Searching expands all departments so you can find people across the org without clicking through each one.
  - Incident followers now match the same chip styling as Pin followers for a consistent look.

  Pin follower removals still follow the recurring-pin update scope prompt, and incident follower removal respects the `incidents.edit` permission.
</Update>

<Update label="May 31, 2026" tags={["Web","Recurring Pins"]} description="Recurring Pin attachments">
  Recurring Pins created from the web dashboard can now include images, videos, and PDFs at creation time.

  Uploads use the same attachment flow as regular Pin creation and prevent submission while media is still uploading.
</Update>

<Update label="May 31, 2026" tags={["Web","Mobile","Pins","Equipment"]} description="Equipment status in Pin creation">
  Users can now change linked equipment status while creating a Pin on web or mobile.

  This keeps equipment condition updates attached to the work being reported, without needing a separate trip to the equipment record.
</Update>

<Update label="May 31, 2026" tags={["Web","Mobile"]} description="Clearer action errors">
  Web and mobile now show clearer default messages when an action fails, including permission-related failures.

  Failed saves, uploads, and edits should now be easier to understand without each screen needing its own custom error message.
</Update>

<Update label="May 31, 2026" tags={["Web","Roles","Permissions"]} description="Roles and permissions cleanup">
  Role management now distinguishes between creating new records and editing existing records.

  The permissions detail view has also been streamlined so admins can scan role access more easily.
</Update>

<Update label="May 29, 2026" tags={["Web","Pins"]} description="Pin group creation">
  Pin groups can now be created directly from the Pin Groups page, making it faster to organize related work without leaving the group list.
</Update>

<Update label="May 29, 2026" tags={["Web","Mobile","Pins"]} description="Due-soon Pins for field users">
  The overview due-soon feed now correctly includes Pins that field users can see through assigned, followed, or created-by access.
</Update>

<Update label="May 28, 2026" tags={["Web","Mobile","Recurring Pins","Checklists"]} description="Recurring series checklist editing">
  Recurring series checklists can now be edited directly on web and mobile.

  This includes future-start series that have not generated their first instance yet.
</Update>

<Update label="May 28, 2026" tags={["Analytics","Notifications"]} description="Tenant-local daily summaries">
  Daily summaries now run according to each tenant's local timezone, so recap data lines up with the correct local business day.
</Update>

<Update label="May 27, 2026" tags={["Web","Recurring Pins"]} description="Editable recurring series clones">
  Cloned recurring series can now be adjusted before creation, including assignment, location, equipment, description, checklist, and form-field details.
</Update>

<Update label="May 27, 2026" tags={["Web","Recurring Pins"]} description="Recurring title and description scope">
  Editing a recurring Pin title or description now follows the same scoped update flow as other recurring changes.

  Users can choose whether to update only one instance or future instances too.
</Update>

<Update label="May 27, 2026" tags={["Inventory"]} description="Inventory quantity notes">
  Inventory notes now include explicit quantity changes for restocks and usage, making the notes feed easier to understand without opening the audit log.
</Update>

<Update label="May 27, 2026" tags={["Web","Pins"]} description="Clear Pin due dates">
  Web users can now remove an existing due date from a Pin, including recurring Pins that use scoped update flows.
</Update>

<Update label="May 27, 2026" tags={["Web","Mobile","Pins"]} description="Resolve language">
  Pin lifecycle language now consistently uses "Resolve" and "Resolved" across web and mobile, aligning the UI with the active resolve workflow.
</Update>

<Update label="May 27, 2026" tags={["Web","Mobile","Authentication"]} description="SSO support">
  Pin now supports WorkOS SSO flows across web, mobile, tenant management, and tenant/user settings.

  Admins can configure tenant-level SSO and user SSO bypass controls.
</Update>

<Update label="May 27, 2026" tags={["Locations","Tenant Management"]} description="Managed Buildings">
  Locations now use managed Building records instead of freeform building text.

  Tenant management includes controls for Buildings, and existing location building values were migrated into managed records.
</Update>

<Update label="May 27, 2026" tags={["Web","Analytics"]} description="Analytics improvements">
  Pin analytics now include an improved date-range picker and a clearer creation-platform visualization.
</Update>

<Update label="May 24, 2026" tags={["Chat","Roles","Pins"]} description="Department Pin chat membership">
  Department Pin chat membership now uses an explicit role setting separate from department notifications.

  This gives admins more precise control over who is auto-added to Pin chats.
</Update>

<Update label="May 24, 2026" tags={["Mobile","Locations"]} description="Mobile map selection fix">
  Mobile map taps now resolve the underlying location even when the current-location blue dot captures the tap.
</Update>

<Update label="May 8, 2026" tags={["Help Center"]} description="Help center launched">
  The Pin help center is now live at [docs.pin.works](https://docs.pin.works).

  The first version includes guides for creating Pins, managing work, using the map, using chat, managing users and teams, working with equipment, inventory, and locations, and reviewing analytics.
</Update>
