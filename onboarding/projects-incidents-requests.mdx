# Projects, Incidents, and Requests

Some work needs more structure than a single Pin. Projects, Incidents, and request links help teams manage larger initiatives, formal incident workflows, and external submissions.

## Projects

Projects organize coordinated initiatives that involve multiple Pins, departments, or workstreams.

Examples include store openings, renovations, seasonal changes, compliance initiatives, or any multi-step operational effort.

## Project visibility

Projects are follower-based. Only project followers can view the full project. If a Pin inside a project is assigned to you, you may still see the Pin in your regular list even if you cannot access the full project.

## Project pages

A project page may include:

- Title and description
- Due date
- Status
- Progress bar
- Linked Pins
- Categories or workstreams
- Documents
- Project chat

The Documents area can include files uploaded directly to the project and attachments surfaced from linked Pins.

## Project categories

Categories group project Pins into workstreams. For example, a store opening project might include Construction, Design, and Opening Plan categories.

## Project chat

Use project chat for high-level coordination. Use individual Pin chats for task-specific conversation.

## Incidents

Incidents are used when a situation requires a formal security, safety, or medical record.

Unlike regular Pins, incidents can include a status timeline, structured reports, follower-based visibility, and a dedicated incident chat.

## Incident types

**Security** incidents can include theft, suspicious activity, property damage, and other security events.

**Safety** incidents can include hazards, evacuations, fire alarms, and other safety events.

**Medical** incidents can include guest or staff injuries, medical emergencies, and health events.

## Incident visibility

Incidents are follower-based so sensitive information remains visible only to the right people.

## Incident timeline

An incident may move through statuses such as:

- Open
- Dispatched
- On Scene
- Cleared
- Closed

## Incident reports

Incident reports are structured records that document what happened. Multiple reports may be added to an incident and stored permanently as part of the incident record.

## Convert a Pin to an incident

If a regular Pin also requires formal incident documentation, use the Pin actions menu to convert it to an incident if your permissions allow it.

## Tenant or external requests

Your organization may provide a request link or QR code that lets tenants, contractors, or external users submit work without a Pin account.

Submitted requests become Pins, are routed to the right department, and follow the same assignment, tracking, and completion workflow as internally created Pins.

No Pin account is required for the person submitting the request.
